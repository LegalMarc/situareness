# O3 implementation contract

## Architecture and privacy

The Chrome extension provides a read-only room; a separately configured Home Assistant integration monitors NWS independently. Public JSON examples contain New York City and Washington, DC only. Browser settings and exports include watched locations and are sensitive. Private JSON working files belong under `ignored-resources/private-config/` and must not enter release bundles or Git history.

## Room

Collect NWS active alerts, USGS `all_hour` earthquake reports, and BBC feeds using packaged adapters. NWS and USGS target one-minute polling and BBC five-minute polling, subject to provider, network, and browser scheduling delays. USGS reports are post-event, not earthquake early warning. Display source health, times, stale and failed states, and coarse location associations without implying a household impact. Preserve bounded collections, safe links, and validation. Room settings reside in Chrome storage; a changed JSON file requires import to update that storage.

The optional `room.context_dashboard` is a non-authoritative third-party display link, initially World Monitor. It is independent of the source collectors and never authorizes an alarm. Legacy `primary_dashboard` imports remain supported. Fresh current NWS items receive retention priority within bounded history; non-expired retained items from a disabled, failed, or overdue source carry a visible cached badge (`Cached · source unavailable`), including NWS items also marked `Not in latest results` (missing or unknown NWS lifecycle defaults to cached when unavailable, whereas `expired` renders only `Source expiry passed`). All items have a seven-day collection-age bound. Global-cap history loss is disclosed separately from freshness and provider truncation, with a seven-day last-loss window and a reset when all previous source identities are removed. Disabled sources display neutral health and are excluded from enabled-source health rollups; an all-disabled collector is neutral. Startup collects overdue sources, and manual collection updates cadence. Bundled configuration failures produce an explicit room error.

## Home Assistant

This section is the normative specification for the Home Assistant integration. See [CAP source evidence and policy](../reference/cap-cancellation.md) for primary-source rationale.

### Qualification and per-feature quarantine

- Collect active NWS alerts across configured states cleanly per poll (deduplicating identical copies and allowing >1,000-feature multi-state bursts under the 50-second overall fetch deadline, 25s/page timeout, 50-page, and 8 MiB/page transport bounds without aborting the poll); transient HTTP, timeout, oversized-response, or pagination failures fail the poll without clearing prior state or latching degraded mode.
- Qualify only current `Actual` NWS `Alert`/`Update` messages issued within the 7-day `MAX_ACCEPTANCE_AGE` with valid in-range timestamps (years `2–9998` to avoid horizon overflow), complete CAP identity/reference tuples, strictly earlier referenced `sent` timestamps, `sent <= now + 5m`, valid action windows (`effective`/`onset`/`expires`/`ends`), a configured household point inside supported Polygon/MultiPolygon geometry, and an approved event and protective-instruction prefix rule.
- Reject unknown geometry, missing footprints, test messages, cancellations, and expired alerts from qualification. Only valid `Actual` `Update` and `Cancel` messages can supersede referenced predecessors; non-`Actual` (`Test`, `Exercise`, `System`) or `Alert` messages never hide or supersede referenced `Actual` alerts or migrate their pending outbox items. An `ended_or_absent` transition does not establish an official cancellation, and official cancellation is learned only on a later poll.
- Isolate malformed, oversized, future-dated (`sent > now + 5m`), or conflicting-duplicate non-cancellation features in per-feature/per-lineage quarantine without failing unrelated valid alerts, preserving pending retries in suspension and preventing raw references from suppressing independent branches.
- When a malformed or oversized non-cancellation feature has an extractable NWS feature `id` (`https://api.weather.gov/alerts/...`), scope quarantine to `[feature_id, *absent_unreferenced_valid_refs]` (quarantining `feature_id` and absent prior records in `valid_refs` that are not referenced by another valid current candidate, even when `properties` is non-object or a reference `@id` is invalid, so unverified raw references on a non-`Cancel` feature cannot suppress a valid candidate currently present in the feed).
- Trigger poll-wide `quarantine_ambiguous: true` (suspending all lineages for that poll without counting ordinary poll-wide `quarantine_all` suspensions lacking `prior_state == "active"` or in-window actions toward the 1,000-record overflow cap, and raising `situareness_degraded`) only when a feature `id` cannot be safely extracted or unique quarantined IDs exceed 5,000 in one poll.
- Reconcile updates, deduplicate equivalent active lineage, persist state via private `Store(..., private=True)`, target all configured phones and only affected-location speakers, require explicit `live_enabled` and `commissioning_passed` gates (both defaulting to `false`), make up to three total attempts (`MAX_ATTEMPTS = 3`: one initial call plus up to two retries) for failed or uncertain deliveries rather than sending repeated reminders (at-least-once delivery: a crash after Home Assistant accepts a service call before persistence can duplicate that delivery group), bridge equivalent inactive actions for at most 15 minutes, and invalidate prior pending targets on changed event or instruction.

### CAP cancellation and continuing segments

- Treat CAP references as directed evidence rather than whole-component cancellation authority. Do not infer cancellation scope from area names, VTEC equality, or overlapping UGCs.
- Keep explicitly cancelled records (including retained `state == "cancelled"` records whose `Cancel` aged out) blocked for `MAX_ACCEPTANCE_AGE` (7 days) before transitioning absent expired records to `ended_or_absent`.
- Isolate invalid or future-dated (`> +5m`) `Actual Cancel` records with recoverable targets in `uncertain_targets` without persisting raw `lineage` edges and without promoting them to authoritative cancellation when clocks advance.
- Quarantine unreferenced pre-cancellation uncertain records and suspend pending retries while current (`cancellation_uncertain`, `partial`); resolve absent uncertainty to `ended_or_absent` on clean polls (keeping existing suspended outbox items bounded by the 15-minute outbox window).
- For valid unreferenced continuing segments issued at or after a partial cancellation (`sent >= cancelled_at`), keep repeating pre-cancellation actions suspended in `quarantined` state while evaluating distinct new qualifying actions normally as `active`. Keep independent sibling branches eligible.

### Bounded storage and headroom

- Enforce caps of 1,000 stored records, 100 references per alert, 100 action fingerprints per record, 5,000 unique quarantined IDs per poll, and 5,000 outbox targets.
- Retain protected `Cancel`/tombstone components for 7 days (`MAX_ACCEPTANCE_AGE`) from the latest component timestamp, bounded per record at `min(timestamp, updated + 5m)` and clamped at `MAX_TIMESTAMP` (`9998-12-31T23:59:59+00:00`) so future-dated or far-future inputs cannot extend retention or persisted `degraded_until` past reloadable bounds.
- In `_bound_records()`, classify protected history (`protected`) using these rules:
  - Protect cancellation components plus all `active`, `cancelled`, cancellation-lineage (`cancel_message` or `uncertain_targets`), `prior_state == "active"`, `<=15m` bridge-window `actions`, and scoped (`not quarantine_all`) `quarantined` records even when absent from `seen` or `graph_events`.
  - Exclude poll-wide `quarantine_all` / `unconfirmed` suspensions without active prior state or `<=15m` actions, ordinary `ineligible` feed items, and non-actionable hidden `superseded` placeholders outside actionable or cancellation groups. Consequently, >1,000-feature ambiguous bursts truncate cleanly to 1,000 records without falsely latching a 7-day block, and `_healthy_snapshot` safely falls back via `.get()` to `"ineligible"` and per-event `qualify()` reasons for evicted current `ineligible` events.
  - When `len(protected) > 1,000`, prioritize `protected`, actionable, and `quarantined`/`unconfirmed` records, and extend `degraded_until` (clamped at `MAX_TIMESTAMP`, floor `now + MAX_ACCEPTANCE_AGE`) to the latest `dropped_horizon` across evicted protected/cancellation components (`eid in protected`).
- When malformed, oversized, or conflicting `Actual Cancel` records have recoverable non-empty reference URLs within the 5,000-ID poll cap, quarantine only those targeted lineages and directed descendants (`cancellation_uncertain`, `partial`).

### Degraded states and `outbox_overflow`

- **Evidence/storage degraded modes (`evidence_degraded: true`, `output_blocked: true`):**
  - `cancellation_evidence_overflow`: Protected history exceeds 1,000 records (`degraded_until` at least 7 days and covers evicted protected/cancellation `dropped_horizon`; `withheld_count` reports qualifying plans stripped on overflow). While any active evidence/storage `degraded_until` has not expired, higher-precedence active reasons (`conflicting_cancellation > malformed_cancellation > journal_lost > cancellation_evidence_overflow`) keep `degraded_reason` precedence over lower-precedence concurrent triggers so intermittent concurrent triggers neither alternate `degraded_reason` nor reset `degraded_at`, while still enforcing `max(..., overflow_horizon)` on `degraded_until`.
  - `malformed_cancellation` / `conflicting_cancellation`: An `Actual Cancel` lacks recoverable target references or exceeds the 5,000-ID quarantine cap, or conflicting cancellation evidence cannot be scoped safely (`degraded_until` at least 7 days, or any concurrent `overflow_horizon`).
  - `journal_lost`: A previously initialized config entry's store goes missing (`persisted` is `None` or `{}`). Latch with stable non-future `degraded_at` in `journal_lost_at` across pre-fetch failures (resetting future `journal_lost_at` after clock rollback), persist before fetching, and set `degraded_until >= detect_now + MAX_ACCEPTANCE_AGE` clamped at `MAX_TIMESTAMP` (rotating stale `journal_lost_at` past 7 days and clearing `journal_lost_at` on post-fetch saves, non-empty store loads, or `malformed_store` entry). Do not classify an already-recovered initialized entry whose main store vanished as `malformed_store` merely because a stale `.corrupt.*` backup failed to unlink earlier.
  - `malformed_store`: Persisted JSON fails decoding (`JSONDecodeError`, `.corrupt.*` backups when not already recovered), major-version validation (`UnsupportedStorageVersionError`, `NotImplementedError`, `ValueError`), or deep schema validation (`bool` checks on `initialized`/`was_live`, `degraded_reason` in allowed persisted reasons, required record `state` and optional non-`null` `prior_state` in `{active, ineligible, ended_or_absent, quarantined, unconfirmed, superseded, cancelled}`, outbox `<= 5,000`, non-bool non-negative `int` `expired_unsent`, valid `expired_unsent_at`/`expired_unsent_until` ISO timestamps, and valid optional `expired_unsent_reasons` / outcome `"reason"` values in `{age, clock_rollback, target_removed}`); unexpected internal/runtime errors raise `ConfigEntryNotReady` for retry. Skip collection and writes to preserve disk data (`degraded_until: null`; mark `journal_initialized: true`).
- **Capacity mode (`outbox_overflow`, `evidence_degraded: false`, `output_blocked: false`, `partial: true`):**
  - When queued plus newly planned targets exceed 5,000, pre-drain one up-to-100-target batch first if deliverable outbox items exist, then queue whole plans with non-empty `new_items` atomically up to 5,000 targets (already-queued plans with `new_items == []` are never counted as overflowing, dropped, or stripped). Strip/withhold only overflowing plans (`withheld_count`), and run a post-queue delivery pass with remaining per-poll budget (`100 - pre_drain_attempts` within the 30-second poll deadline) so newly queued first-attempt items deliver immediately unless pre-drain exhausted all 100 poll attempts or the 30-second deadline.
  - Set `degraded_reason: "outbox_overflow"` and `degraded_until = now + MAX_AGE` (15 minutes), continue bounded queued delivery (max 100 targets/poll, first-attempt `attempts == 0` targets ahead of retries while preserving FIFO within each tier, 30s deadline, coalesced to at most one store save per 10-target group covering pruned expired items and completed deliveries, noting 10KB-max instructions serialize tens of MB across up to `11` saves/poll normally or up to `22` saves/poll during pre-drain passes, and excluding `outbox_overflow` from `last_degraded_poll` age freezing), surface active `active_count`, `deliverable_count`/`suspended_count`, and `expired_unsent`, and clear automatically when capacity fits.
  - Unexhausted (`0 <= attempts < MAX_ATTEMPTS`) queued targets for a currently active (or `prior_state == "active"` suspended) alert that fail validation via 15-minute `MAX_AGE` expiry (`"age"`), backward clock rollback (`created > now`, `"clock_rollback"`), or removed targets (`"target_removed"`) are recorded via `expired_unsent`, `expired_unsent_reasons`, `partial: true`, outcomes (`{"expired": True, "reason": ...}`), and `situareness_degraded` latched additively across clean, degraded, and `_stopped_health()` snapshots until cleared 7 days after the latest expiration (resetting healthy non-config `acknowledge_rejected`) or on reload via valid `acknowledge_degraded_at`.

### Recovery, notifications, and lifecycle

- Offload heavy per-page parsing/normalization and post-fetch coordinator CPU work: async HTTP pagination (`50`s total / `25`s per-page timeout) runs in `collector.fetch()` while per-page JSON decoding and feature normalization/quarantine offload via `asyncio.to_thread`; post-fetch coordinator work (`_valid_persisted_store`, candidate/conflict resolution, `reconcile`, outbox migration/`lineage_index`, target generation, `_strip_withheld_actions`, deliverable-count qualification checks, and `_select_deliverable_batch`) runs via `hass.async_add_executor_job`, and only per-group `<=10`-item `qualify`/`pending_valid` delivery rechecks run on the event loop between saves. Keep `_healthy_snapshot` inside `_update_once`'s `try:` block so unexpected snapshot errors raise `UpdateFailed`.
- Surface `cancellation_uncertain`, `acknowledge_rejected`, and latched `expired_unsent` truthfully across degraded, healthy, and stopped snapshots, preserving config-level invalid/naive/over-length/future `acknowledge_rejected` across mid-session clears, excluding `events`, `last_success`, `degraded_at`, and `degraded_until` from recorder history, and reporting `withheld_count` alongside `planned_count`.
- Keep initial `degraded_at` stable across consecutive evidence/storage degraded polls (`degraded_reason != "outbox_overflow"`) and identical-reason `outbox_overflow` polls while extending `degraded_until` so reload acknowledgements do not race intervening polls.
- Raise `situareness_degraded` once per `(reason, live, acknowledge_rejected, expired_count, tuple(expired_unsent_reasons))` on load and pre-fetch (qualified in shadow mode with live output disabled):
  - Tailor recovery guidance per reason: `.storage`/`.corrupt.*` manual repair/replacement strictly for `malformed_store`; continued delivery/capacity auto-clear/expiration details for `outbox_overflow`; 7-day horizon/`acknowledge_degraded_at` guidance for `journal_lost`, `cancellation_evidence_overflow`, and feed cancellation triggers (including concurrent overflow notes).
  - Attribute `expired_unsent` causes truthfully from `expired_unsent_reasons` (15-minute window expiry, backward clock rollback `created > now`, and target removal from `situareness.json`) and surface reason-accurate rejected/same-reason re-latched `acknowledge_rejected` notices (healthy, degraded, and concurrent `quarantine_ambiguous`).
  - Dismiss `situareness_degraded` on recovery/expiry, coordinator stop, entry unload, abandoned or failed initial setup (`SETUP_RETRY` transitioning to `not_loaded`, `setup_error`, or `migration_error` when disabled, errored, or unloaded), or before deleting the store and `.corrupt.*` backups on entry removal; automatically delete stale `.corrupt.*` backups on the first post-`malformed_store` save (logging warnings on `OSError` and keeping cleanup armed until all backups are removed).
- Clear evidence/journal degradations after `degraded_until` on a clean poll once triggers leave, or via one-shot non-future `acknowledge_degraded_at` evaluated at load (`degraded_at <= acknowledge_degraded_at <= load_now`):
  - Track `_ack_cleared_reason` so Poll 1 marks `acknowledge_rejected: true` only if the cleared reason itself re-latches.
  - Clear latched `expired_unsent` alongside `self.degraded` (or while healthy) only if `expired_unsent_at` is present and `expired_unsent_at <= acknowledge_degraded_at <= load_now`; if `expired_unsent_at` is missing or later, clearing `self.degraded` leaves `expired_unsent` latched, and while healthy invalid/naive/over-length/future/premature/missing-anchor/already-consumed values set `acknowledge_rejected: true`.
  - Reject only non-string, empty, or C0/DEL/C1 control-character `acknowledge_degraded_at` values in `config.validate(raw)`; enforce format, timezone, `<=100` length, non-future, `>= degraded_at`, `malformed_store`, and bounded `<=100`-entry `consumed_acknowledgements` checks at coordinator load without taking monitoring offline.
- Recovering from `malformed_store` (repairing JSON, deleting store + `.corrupt.*` backups or replacing data with `{}` to enter `journal_lost`, or removing/re-adding the entry) or acknowledging `cancellation_evidence_overflow` early discards tombstones and can allow in-window alerts to re-evaluate. Pre-degradation outbox retries freeze `created` ages via `last_degraded_poll` during non-`outbox_overflow` degraded holds (up to 7+ days) so surviving active alerts resume retrying without duplication once resolved.
- Stop cancels only internal in-flight fetch tasks cleanly, checks `_stopping` before post-fetch store writes and delivery (`async_unload_entry` stops the coordinator before unloading platforms, so stop completes without post-stop writes), and returns `_stopped_health()` preserving non-degraded suspended counts; external cancellation of the outer refresh task propagates `asyncio.CancelledError`. No horn adapter exists; service acceptance is not proof of human receipt.
